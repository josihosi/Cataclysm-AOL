## Observed edge case

During a Windows camp playtest using world `TestSetup00`, the game crashed at approximately 2026-09-24 16:23:44 while a bandit camp scout was active.

The debug log shows the bandit camp dispatched a scout earlier in the same play session. At 16:23:31, the scheduler logged `dispatches_planned=1`, `dispatches_applied=1`, `materialization_attempts=1`, and `members_materialized=3`; subsequent performance lines show `active_job_mix=camp_style:scout=1`. Shortly before the crash, bandit threat-observation messages repeatedly reported `target=player@131,143,0`.

The Windows crash was an access violation (`0xc0000005`, read) in `item::has_flag`. The faulting instruction read the `item::type` pointer at `this + 0x20`; the `this` pointer in the dump was invalid (`RBX=0x2100000000`, attempted read at `0x2100000020`). This establishes an invalid item pointer at the crash site, but not how it became invalid.

The unwound stack enters `Character::cache_has_item_with` / inventory traversal from the bandit local-zombie threat-observation path (`live_bandit_local_zombie_read_impl`), during structural bounty outing maintenance in `game::do_turn`. The stack does not show cannibal ecology in the faulting path.
