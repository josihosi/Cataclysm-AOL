# Source-grounded review decisions

Activation: use canonical game::load_npcs and exact active/tracker identity checks, retain strategic orders, and exclude locally committed hostile IDs from generic overmap travel. Current source only excludes abstract approaching hostile members. This preserves the authoritative order for return while preventing a stale strategic step during local combat. Consistent active parties must be idempotent; partial admission cannot be credited. The analogous upstream production design also separates canonical loading/on_load from generic travel; consulted https://raw.githubusercontent.com/CleverRaven/Cataclysm-DDA/master/src/game.cpp and https://raw.githubusercontent.com/CleverRaven/Cataclysm-DDA/master/src/do_turn.cpp on 2026-09-10. Upstream is comparative design evidence, not proof of this fork's behavior.

Sound: retain the existing 180-minute sound lifetime and 360-minute actual-check cooldown. New remote sound observations leave check/scout times unset, and refresh preserves an existing check before upsert, which replaces records. A fresh uncertain sound remains normally eligible rather than forcing an outing. The helper proposed clearing legacy stamps when last_outcome is camp_observer_sound; this was not adopted because a later remote observation can overwrite provenance for an earlier real check. Preserve ambiguous legacy values for their finite cooldown; do not perpetuate them on new reads. Boundary checks and an actual favorable native route remain required.

NPC testing: the source inventory contains 12 named primary tokens plus attack and move dynamic routes, with look routes using secondary requests and inventory wear/wield/activate/drop branches. A queued enum inventory would miss these. The helper's phrase deterministic localLLM response is replaced by actual controlled prompts and preserved model output; native evidence cannot depend on injected responses or guaranteed model compliance. E4B is the owner's chosen baseline, not a proven comparative winner. Existing qualification explicitly has no matched E2B/E4B benchmark.

API comparison: the owner authorizes failed E4B cases to be logged as bugs and rerun through a cheap OpenAI model with existing credentials. Current source already defaults to gpt-4.1-mini through any_llm Chat Completions, with no reasoning control. Selected that low-cost non-reasoning model to use the established request shape rather than making this comparison depend on a new GPT-5 parameter adaptation. Official model page https://developers.openai.com/api/docs/models/gpt-4.1-mini (opened 2026-09-10) lists $0.40 input and $1.60 output per million tokens, Chat Completions support and no reasoning step. GPT-5.6 Luna was considered ($0.20/$1.20) but its readiness with this installed request adapter was not established. No API key value was read, no provider request was sent and no API availability claim is made by this FS review; setup and the actual failed-case retry are explicitly commissioned to Sol. Preserve provider-specific results and usage, and prevent API cleanup from unloading the owner's Ollama server.
