# Alignment manifest

This is a design compass for agentic workflows. It does not grant runtime authority, replace the
DFS, or add another gate. Use it to notice when locally reasonable instructions combine into a
globally unreasonable machine.

## Build the workflow around the outcome

The system exists to help capable agents build and prove the requested result. State, roles,
ledgers, clocks, supervisors, tests, and dashboards are supporting structure. None is the product,
and none should become work merely to keep itself satisfied.

Describe work as an outcome with visible, coherent spokes. Let one worker own diagnosis, repair,
testing, and evidence return while the outcome and safety boundary remain valid. A failed tactic is
usually the next observation, not a reason to detach the task, reset the clock, or manufacture a new
administrative lifecycle. Keep small work small; do not force every change into a ceremony.

## Trust the agent twice

Trust the worker to change tactics, repair the implementation or harness, retrieve the needed
evidence, and stop when the outcome is honestly settled. Trust the coordinator to judge results,
reshape the route, switch independent work, and decide when a strategy has converged or failed.

When an agent struggles, first inspect what it was told and what the interface exposed. Worker error
is often instruction or interface evidence before it is capability evidence. Improve context,
state visibility, and reusable actions before adding warnings, prohibitions, retries, or a special
case. Scrutinize the instructions that produce behavior more closely than the behavior itself.

Trust is not pretending errors cannot happen. Mechanical owners should still protect facts an LLM
cannot safely reconstruct: identity, binding, ownership, single-use transitions, immutable receipts,
cleanup, citations, contradictions, and evidence ceilings. The model owns judgment and trajectory;
the machine owns durable truth.

## Structure, not a prison

Good structure makes the next meaningful action obvious and recoverable. It gives the agent handles:
current outcome, accepted evidence, remaining uncertainty, available actions, active ownership, and
an honest way to finish or change direction. It should reduce context and coordination cost.

A prison tells the agent how to think, converts every discrepancy into a stop condition, demands
proof-shaped paperwork, or requires permission that no real owner reserved. A warning sign is an
agent that knows the correct next action but is forbidden from taking it because two administrative
descriptions disagree.

The coordinator uses the supervisor to preserve continuity. The supervisor does not manage the
coordinator's reasoning. It should launch, retain durable handoffs, enforce exclusive transitions,
surface failures, and then get out of the way.

## Loop guards protect freedom

Loop guards are the counterweight to flexibility, not its replacement. They should detect repeated
frontiers, unchanged failures, duplicate ownership, lost workers, or reconnect churn. On detection,
return the observed mismatch and relevant context to the coordinator, giving it bounded corrective
opportunities to repair the projection or choose another route. Stop only when repetition remains
unchanged, ownership is unsafe, or no lawful progress route exists.

Guard the repeated state transition, not a preferred strategy. Do not treat a valid wait, mutation
handoff, worker result, or deliberate task switch as “no progress.” A fuse retires a stuck tactic;
it must not silently declare the unfinished outcome impossible. Retry counts and time bounds come
from explicit policy, platform contracts, or measured mechanics—not intuition.

## Proof without bureaucracy

Preserve eagerness to test and prove, but ask for the smallest evidence that settles the causal
question. Apply intellectual scrutiny and administrative leniency: challenge false conclusions,
unsafe actions, identity failures, causal ambiguity, concealed contradictions, and evidence
promotion. Repair derivable clerical defects without replaying authentic work.

An agent may act as an objective witness. Give it a plain claim, material proof and contradiction,
accepted evidence, uncertainty, forbidden shortcuts, and evidence ceiling. Let it observe, choose,
act, repair, rerun, cite, and conclude `proved`, `contradicted`, or `inconclusive`. Do not replace
judgment with a scenario-specific form whose completion becomes confused with truth.

Tests are executable explanations of the intended workflow, not constitutional authority. When a
test encodes an accidental process, change or delete the test. Prefer behavioral tests that admit
multiple correct strategies and reject concrete false outcomes.

## Authority must name its owner

Distinguish technical authority from human permission. A coordinator brief can authorize ordinary
in-scope work; a validated selection can mint a single-use run receipt; a report can carry only its
fixed evidence ceiling; and a genuinely human judgment remains human because the outcome explicitly
assigns it there. Do not infer a human gate from words such as “explicit,” “selected,” or
“authority.”

If an agent reports unavailable authority, trace the complete path before projecting a blocker:
who owns the decision, what exact operation was attempted, what response refused it, and whether the
brief already supplied the necessary authority. No runtime rejection means “external permission is
missing” remains an inference, not a fact.

## Keep context aligned

Before strengthening a rule, compare the whole instruction path:

- requested outcome and frozen DFS;
- active ledger and current durable state;
- coordinator brief and worker skill;
- harness/runtime affordances and error messages;
- tests, examples, dashboard language, and historical workarounds.

A correction is incomplete when one layer still teaches the old behavior. Research surrounding
mechanisms and competing owners, then simplify the complete path. Mutations should perform this
structural overpass rather than append one more sentence to whichever file exposed the symptom.

## Practical smell test

Pause and realign when any of these appear:

- the same fact is rediscovered across several worker windows;
- a worker stops at a repair it was already empowered to make;
- a coordinator asks a human for a choice the outcome already delegated;
- a valid handoff is classified as inactivity;
- documentation quality causes authentic gameplay or testing to be replayed;
- a regression test prevents improving the workflow it was meant to protect;
- dashboard state disagrees with process or durable ownership truth;
- more rules are proposed before the contradictory existing rules are traced.

The desired machine is simple to control because it gives the agent trustworthy state and useful
actions. It keeps churning toward red outcomes, but it remains a tool in the agent's hands.
